結論：まずVOICEVOXを使い切る

対象はNotebookLM音声でもサムネイルのロボットでもなく、紫ノ宮澪と麦野透が立ち絵で掛け合う講義動画システム。最初にすべきことはTTSの全面交換ではなく、固定されている話者スタイルを、セリフの感情と立ち絵ポーズに合わせて切り替えることです。

Phase 1 · 最優先

VOICEVOXスタイル演出

現行APIのまま、style・話速・抑揚・間をセリフ単位で制御。動画合成部分は変更不要。

Phase 2 · 本命

AivisSpeechへ差し替え

VOICEVOX互換HTTP APIを活かし、多スタイルモデルまたは将来の独自音声へ移行。

Quality benchmark

ElevenLabs v3で上限確認

自由な感情指示の品質上限を短い比較試験で確認。直ちに本番基盤にする必要はない。

推奨判断: 1〜2日でVOICEVOX版のA/Bテストを作り、その結果に満足できなければAivisSpeechを比較する。独自声の学習は、キャラクターの反応設計が固まってから着手する。

正しい対象システム

対象実装は、同リポジトリの別ワークツリー worktree-lecture-video-prototype にある src/lecture/ 系です。URLから講義台本を作り、2人の立ち絵・口パク・字幕・音声をFFmpegで同期するプロトタイプです。

解説役紫ノ宮澪。現状の声は VOICEVOX「もち子さん セクシー／あん子」style_id 66。
聞き役麦野透。現状の声は VOICEVOX「満別花丸 ノーマル」style_id 69。
映像演技全セリフに metan_pose / zunda_pose があり、表情・ポーズを切り替える。
音声演技speaker ごとの固定 style_id と固定 speedScale だけで、感情は未指定。
良い土台はすでにあります。 セリフ単位のWAV、実測音声尺、ポーズ切替、口パクが分離されているため、TTSを高度化しても assemble.py のタイムライン設計をほぼ維持できます。

現在のボトルネックは「声の演出層」がないこと

現状の tts.py は、話者から style_id を1つ引き、全セリフへ同じ話速を適用します。一方、立ち絵側には「褒める・注意する・からかう・照れる・混乱する」といった意味のあるポーズがすでにあります。映像には感情があるのに、音声は同じ読み方のままです。

現状起きること必要な変更
style_id が話者ごとに固定喜び・注意・照れでも同じ声質セリフ単位のstyle選択
speedScale だけを変更テンポは変わるが演技にならない抑揚・音高・音量・前後の間をプリセット化
ポーズと声が別々ウインクしているのに平板、混乱しているのに断定口調共通の delivery を単一ソースにする
感情の強度がないスタイル切替が大げさになりやすいintensity で弱・中・強を制御
重要: 「リアルさ」は声質だけで決まりません。キャラクターらしい間、語尾、強調位置、感情の立ち上がりと戻りが、立ち絵の変化と同時に起きることが効きます。

追加するのは小さな VoiceDirector

台本に、発話者の演技を示す delivery と強度 intensity を追加します。VoiceDirectorは、その意味ラベルを各エンジン固有の style・抑揚・間へ変換します。これにより、VOICEVOXからAivisSpeechやクラウドTTSへ替えても台本スキーマを維持できます。

{
  "speaker": "metan",
  "text": "透くん、そこに気づいたのは鋭いわ。",
  "reading": "とおるくん、そこにきづいたのはするどいわ。",
  "delivery": "praise",
  "intensity": 0.45,
  "pause_after": 0.35,
  "metan_pose": "praise",
  "zunda_pose": "praised"
}
設計原則: ポーズ名から声を直接決め打ちするのではなく、delivery を声と立ち絵の共通意味にする。非話者側のリアクションは、従来どおり別のposeで表します。

VOICEVOXだけでも、まだ大きく改善できる

VOICEVOX ENGINEは、/audio_query で得たクエリの話速・音高・抑揚・音量・前後無音などを変更してから合成できます。また、話者が対応していれば2スタイル間のモーフィングも可能です。モーフィングの可否はAPIで確認する必要があります。VOICEVOX ENGINE API

なぜAivisSpeechが次の一手か

AivisSpeechは、VOICEVOX互換のHTTP API、文ごとのスタイル・話速・テンポ・アクセント調整、辞書、CPU推論を掲げています。AivisHubには喜び・怒り・悲しみ・驚きなどを持つ多スタイルモデルがあり、既存の synthesize() 境界を維持しやすい選択です。モデルごとのライセンス確認は必要です。AivisSpeech公式 / AivisHub

独自声を持つならStyle-Bert-VITS2

Style-Bert-VITS2は、感情・発話スタイルを強度込みで制御し、音声データから複数のスタイルベクトルを作れます。学習済みモデルをAIVMへ変換してAivisSpeechに載せる経路も公式に案内されています。最大の価値は「澪と透だけの声」を持てることですが、同意済みの録音、収録設計、データ整備、学習、品質管理が必要です。Style-Bert-VITS2公式リポジトリ

ElevenLabsは置換候補よりベンチマーク

Voice Designは年齢・性格・声色・感情・話速を文章で指定して新しい声を作り、保存できます。Eleven v3は幅広い感情と音声タグに対応します。一方で、公式自身がVoice Designを探索・反復向けとし、一貫性の最上位はProfessional Voice Cloneと説明しています。日本語の技術用語、長尺での声の安定、クラウド費用を含め、まず12セリフだけ比較するのが合理的です。ElevenLabs Voices / Voice Design guide

声のリアルさより先に、2人の演技規則を固定する

紫ノ宮澪 — 余裕のある優しい先生

  • 基準は落ち着き、明瞭さ、知性、親しみ。
  • 説明ではテンポを一定にし、重要語だけを強調。
  • 褒める時は声量より明るさと柔らかい語尾。
  • 注意は怒りではなく、話速を落として低めに。
  • からかい・ウインクは短く。長く続けない。

麦野透 — 素直で好奇心のある少年

  • 基準は聞き取りやすさ、誠実さ、少し控えめ。
  • 疑問は語尾だけでなく、考える短い間を入れる。
  • 理解した瞬間は話速と明るさを少し上げる。
  • 照れは囁きにしすぎず、声を小さくして間を取る。
  • 驚き・動揺は短い句へ分け、常時ハイテンションにしない。
映像との合わせ方: ハート瞳や赤面など大きな立ち絵リアクションは、音声でも感情ピークを1か所だけ作る。逆に通常の説明ポーズでは、TTSの派手なスタイルを使わない。この差が演技を本物らしく見せます。

検証は3段階、同じ12セリフで比較する

01

現行VOICEVOXのA/B/C比較

A＝現在の固定style、B＝style切替、C＝style＋抑揚・間・対応時のみモーフィング。澪と透それぞれ6感情、合計12セリフを同一テキストで生成します。

02

AivisSpeechの既存モデルを2候補ずつ試す

VOICEVOX版で表現不足だった感情だけを比較。澪は落ち着き・からかい・注意、透は疑問・喜び・照れを優先します。

03

ElevenLabs v3を品質上限として1本だけ作る

同じ12セリフと立ち絵で生成し、クラウドTTSに替える価値があるほど差が出るかを確認します。

評価項目

項目見るもの合格の考え方
キャラクター同一性感情が変わっても同じ澪／透に聞こえるかスタイル切替で別人化しない
立ち絵との一致praise、confused、flustered等が声でも伝わるか画面を見ながら違和感がない
感情の識別音声だけで狙ったdeliveryを判別できるか強さより方向が正しく伝わる
講義としての信頼感感情が技術説明を邪魔していないか5分以上聞いても疲れない
日本語・技術語uv、Python、コマンド、固有名詞の読みreading／辞書で再現可能
再現性同じ入力を3回生成した時のばらつき自動パイプラインで許容できる
切替条件: VOICEVOXのC案で「立ち絵との一致」と「長尺の聞きやすさ」が成立すれば、そのまま本番化。声質そのものがキャラクターに合わない、または感情間の遷移が不自然ならAivisSpeechへ進む。

オリジナル立ち絵でも、声の権利はオリジナルにはならない

VOICEVOXは商用・非商用で利用できますが、ソフトウェア規約に加えて各音声ライブラリの規約に従い、VOICEVOX利用のクレジットが必要です。VOICEVOXソフトウェア利用規約

現行実装で要修正: script_gen.py のクレジットは VOICEVOX:もち子さん ですが、もち子さん公式規約は VOICEVOX もち子さん(cv明日葉よもぎ) の表記を求めています。また、別キャラクターのCVとして使う場合もクレジットが重要です。公開・収益化前に最新規約と用途を再確認してください。もち子さん公式 利用規約/Q&A
  • 動画内または概要欄で、声の出所が澪・透の自前収録だと誤認されない表記にする。
  • VOICEVOX音声を、将来の独自TTS学習データやボイスチェンジャー学習へ流用しない。
  • AivisHubの配布モデルも、アプリ本体とは別にモデル固有ライセンスを確認する。
  • 本当に「澪と透だけの声」を資産化するなら、同意済みの声優・収録者データで独自モデルを作る。
