TL;DR

./web.shを起動してURLを入力するだけで、Claude Maxの 最新Opusが台本初稿を作り、ChatGPT Proの最新Codex Solが技術／編集審査を行う。 VOICEVOXが澪・透の声を作り、 背景、キャラ、文字、配置、口パク、時間同期、動画合成はローカルコードで再現性を守る。

重要: これは「AIに動画を丸ごと作らせる」仕組みではない。 AIは意味判断と創造性が必要な狭い区間だけに置き、見た目が毎回一致すべき区間は Python・Playwright・ffmpegで固定するハイブリッド生成である。
費用の不変条件: AI処理は既存サブスクリプション内だけで行う。 OpenAI API、Anthropic API、Gemini APIなどの従量課金APIは本番経路から呼ばない。

1. 根本原理 — AIの自由度を境界で制御する

生成AIに任せる

  • 情報源の意味をどう噛み砕くか
  • 澪と透にどう掛け合いさせるか
  • どのスライド表現が伝わるか
  • どんな背景モチーフなら目を引くか

正解が一つではなく、文脈理解や発想が価値になる領域。

→

固定コードに任せる

  • キャラの顔・髪・服・見かけの身長
  • 日本語文字とコード表記の正確さ
  • 立ち絵座標、字幕、口パク差分
  • 音声尺、場面転換、最終MP4

同じ入力なら毎回同じ結果であることが価値になる領域。

境界に置くゲート: Claude初稿とCodex審査結果をJSONスキーマで検証し、背景美術案は 許可済みの意味モチーフへ正規化してローカルSVGへ変換する。 AIの出力をそのまま動画へ流さず、検証可能な中間データへ変換してから使う。

2. どのAIモデル／エージェントを、どこで使うか

Claude Opus — 台本初稿

Claude Code CLI / Claude Max / opus alias

入力
抽出済み本文＋キャラ・動画構成の固定プロンプト
出力
会話、スライド、読み、ポーズ、投稿文、サムネイル美術案の初稿JSON
制約
--safe-mode --tools "" --no-session-persistence --json-schema
モデル
opus、effort=xhigh。直前の実試験で解決された主モデルはclaude-opus-4-8
課金
Claude Max内。Anthropic APIキーは使わない

Codex Sol — 技術／編集審査

Codex CLI / ChatGPT Pro / codex exec

入力
元情報＋Claude初稿＋公開前の審査基準
出力
技術的断定、危険なコマンド、説明順、会話、スライドを直した最終JSON
制約
--ephemeral --ignore-user-config --sandbox read-only
モデル
gpt-5.6-sol、effort=xhigh
課金
ChatGPT Pro内。OpenAI APIキーは使わない

審査済み美術案＋ローカルSVG — 自動背景

codex-directed-local-svg / 外部画像APIなし

入力
二段階AIで確定した意味モチーフ＋動画固有の短い美術案
出力
編集可能な16:9 SVGと、Chromiumで描画した1600×900 PNG
制約
人物、文字、ロゴなし。中央に見出し用の高コントラスト余白
再現性
タイトルと美術案からseedを固定し、同じ入力なら同じ図形
課金
ローカル描画のため追加費用なし

VOICEVOX — 話者別の音声合成

専用TTS。LLMでも自律エージェントでもない

澪
もち子さん（セクシー） / style_id 66
透
満別花丸（ノーマル） / style_id 69
入力
審査済み表示文とは別の、音声合成用reading
出力
セリフ単位の24kHz mono WAV

NotebookLM — 従来モードのみ

mode=notebooklmの音声要約経路

役割
ソース追加とAudio Overview生成
対象
既存YAMLとの後方互換。澪・透の講義モードでは使わない
合流点
完成動画をvideo_readyへ置いた後の投稿処理
最高品質の実機試験（2026-07-21）: Python uvの一次情報から、 Claude初稿は約11分34秒、最初のCodex審査は約7分03秒。最終結果は14シーン、 93セリフ、4,166字、最長80字で固定検証エラー0件だった。Claude CLIの modelUsageには主モデルclaude-opus-4-8に加えて内部補助の claude-haiku-4-5-20251001も報告されたため、両方を監査情報へ保存する。
Codex imagegenも利用できる: Codexアプリ内の$imagegenは gpt-image-2を使い、Codexの利用枠として専用サムネイル背景を生成できる。 今回も実際に16:9のuv専用背景を生成し、確定済みキャラと日本語コピーを Pillowで後合成できた。ただし現環境では非対話のcodex execから画像を 保存できなかったため、人が選ぶ特別版に使う。無人Web経路はローカルSVGを維持する。

「AIエージェント」はどこにいるのか

初稿はツールなしのClaude Code CLI、審査は読み取り専用sandboxと承認禁止のCodex CLIで動かす。 本文は先に通常コードで抽出し、両者へ一括入力する。ここで必要なのは外部行動ではなく、 構成・表現・会話を考え、独立した第二視点で照合する推論能力である。全工程を進める「オーケストレーター」は automatorの固定コードであり、AIモデルではない。

モデル名の読み方: 設定はscript_model: opus、 script_effort: max、review_model: gpt-5.6-sol、 review_effort: max。成果物には要求値だけでなく、CLIが報告した実使用モデル、 Claude Max／ChatGPT認証、各役割、metered_api: falseを記録する。 2026-07-21の実試験ではclaude-opus-4-8とgpt-5.6-solを確認した。

3. URLから動画までのデータ変換

① 通常コード

HTML / PDF / GitHub READMEから本文を抽出し、最大4万文字のsource.txtにする。AI自身はWebを巡回しない。

② Claude初稿

最新Opusが本文を意味単位へ整理し、澪・透の会話、スライド、読み、ポーズ、投稿文、背景モチーフの初稿を返す。

③ 初稿ゲート

必須キー、80文字上限、話者、ポーズ、テンプレート別フィールド、段階表示を検証。不正なら指摘付きで1回だけ再生成する。

④ Codex審査

最新Solが元情報と初稿を照合し、技術的断定、安全性、説明順、口調、読み、スライド同期を直す。

⑤ 最終ゲート

同じ固定検証を再実行。不正なら具体的エラーを添えてCodex審査を1回だけやり直し、それでも駄目なら停止する。

⑥ 2経路へ分岐

scenesは動画本体へ、thumbnail_textとthumbnail_visual_promptはサムネイルへ進む。

⑦ 固定合成

VOICEVOX、Playwright、Pillow、ffmpegが、検証済みデータを音声・画像・動画へ変換する。

⑧ 成果物契約

LectureArtifactsが動画、サムネイル、背景、プロンプト、投稿JSON、モデル情報をWeb・YouTube側へ渡す。

二段階AIが確定する主要データ

データ用途固定コードでの検証
title / description / tagsYouTube投稿情報必須・空文字禁止・VOICEVOX等のクレジットを後段で強制付与
thumbnail_textサムネイルの疑問＋便益コピー2行・各14文字以内
thumbnail_visual_promptローカルSVG用の意味モチーフと美術案240文字以内。許可済みモチーフへ正規化
scenes[].slideタイトル、箇条書き、比較、コード、引用、まとめテンプレート別必須フィールド
text / reading自然な字幕表記とVOICEVOX用読み分け空文字・話者名・セリフ長
metan_pose / zunda_pose会話に合う表情とポーズ利用可能な素材名だけを許可
show_items意味のある箇条書き段階表示単調非減少・最後は全表示

5. 動画本体はどう作られるか

1

段階表示を計画

show_itemsから、各セリフ中に見える箇条書き項目数を確定。

2

スライド描画

固定Jinja2テンプレートをPlaywrightで3840×2160 PNGへ変換。

3

キャラ素材

確定済みの澪・透とポーズ差分を固定座標へ配置。AIで毎回描き直さない。

4

音声合成

VOICEVOXで読みをWAV化し、実測音声尺を次の工程へ渡す。

5

局所口パク

口以外を変えない専用パッチだけを発話中に切り替え、髪や輪郭の揺れを防ぐ。

6

字幕と転換

表示用文をASS字幕へし、章境界に別画像とOtoLogic効果音を挿入。

7

ffmpeg合成

スライド、キャラ、字幕、音声を30fps・1920×1080の1本へ統合。

8

品質を固定

ズームや無意味な上下運動を使わず、座標丸めによる揺れを避ける。

動画生成AIを使わない理由: 数分の解説動画全体を生成モデルへ任せると、 キャラ同一性、文字、口パク、タイミングを再現しにくい。固定スライドと立ち絵を 音声尺に合わせて合成する方が、差分修正と品質管理に向いている。

6. サムネイルは動画ごとに専用生成する

1

AI二段階で美術案を確定

Claudeが内容を象徴する分類、物体、光、構図を提案し、Codexが内容との一致を審査する。

2

ローカルでSVG背景

モチーフをチャンネル共通の色・構図へ変換し、16:9の背景を決定論的に描画。

3

Pillowで固定合成

澪・透の確定素材、2行コピー、白縁、濃色パネル、チャンネル帯を1280×720へ合成。

4

監査情報を保存

SVG原本、PNG、モチーフ、seed、provider、AI実使用モデル、追加API費用なしの記録を残す。

生成AIで変えるもの

  • 題材固有の物体と視覚メタファー
  • 光、流線、奥行き、背景のアクセント
  • 動画内容に沿う疑問＋便益の短いコピー案

毎回固定するもの

  • 澪・透の顔、髪、服、体格、色
  • 左右配置とサムネイル上の見かけの大きさ
  • 日本語見出し、太い白縁、文字パネル
  • 人物・文字・ロゴを背景へ入れない契約

背景方式の設定

設定動作用途
codex-svg（既定）審査済み意味モチーフ＋ローカルSVG描画通常運用。動画ごとに変化し、再現可能
static常に固定背景背景を完全固定した比較試験
最高品質の特別版: 投稿前に人が選ぶ回では、Codexアプリの $imagegenで文字・人物なしの背景を生成し、同じPillow合成へ渡せる。 今回のuv試験では、パッケージ箱と依存関係が一本の光へ収束する背景を gpt-image-2で生成し、確定済みの澪・透と正確な日本語コピーを合成した。 この経路は画像を人が確認して採用する運用であり、無人キューの必須工程ではない。
なぜ「背景だけ」なのか: キャラまで画像生成すると、顔・髪・服・体格が わずかに変わり、チャンネルの認知と差分切替の安定性が落ちる。背景の創造性と、人物・ 文字の再現性を分離することで、クリックを促す変化とブランドの一貫性を両立する。

9. 運用条件と公式出典

ローカル前提

VOICEVOX、Claude Maxログイン済みClaude Code、ChatGPT Proログイン済みCodex、Chromium、ffmpegを使うため、講義モードはmacOSローカル実行を前提とする。

従量課金APIなし

台本はClaude Max＋ChatGPT Pro、背景はローカルSVGで作る。APIキーは不要で、ジョブ数に比例するAI API請求を発生させない。

外部更新

YouTubeへの実投稿だけが公開側の状態を変更する。投稿前の動画・サムネイル・JSONはローカルへ残る。

直列生成

速度よりPlaywright・VOICEVOX・ffmpegの安定性を優先し、講義動画を1件ずつ処理する。

公式情報

  • Codex non-interactive mode — codex exec、構造化出力、パイプライン利用
  • Codex image generation — $imagegen、gpt-image-2、Codex利用枠での手動画像生成
  • OpenAI image generation API — APIキーと従量課金を伴うため、本番経路では採用しない比較対象
  • VOICEVOX 公式 — 音声合成エンジンと利用情報
