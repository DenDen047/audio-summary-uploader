# 動画の形式

2 人のキャラクターの掛け合い（音声＋字幕）と、テンプレート化されたスライドで構成される
講義動画。スライドはセリフの「板書」であり、セリフの復唱ではない。

- `metan`（紫ノ宮澪）: 解説役。完璧な実務能力と大人の包容力を持つ先生。丁寧で
  落ち着いた大人の女性の口調で、相手を急かさず、失敗を恥にしない。通常の説明では
  主語と述語を備えた自然な文を使い、体言止めや説明書のような断片文を避ける。透の
  不安や淡い憧れには気づいているが利用しない。軽くからかう時だけ、結論をすべて
  言い切らず、短い間を作ってもよい。
- `zunda`（麦野透）: 聞き役。純朴で控えめな少年。「です・ます」を基本に、分からない
  ことを正直に尋ねる。自信は弱いが観察は細かく、ときどき澪の説明の飛躍を見つける。
  「〜のだ」など既存キャラクター固有の語尾は使わない。「もう迷いません」のような
  宣言調の不自然な要約を避け、状況に応じて「もう大丈夫です」「これならできそうです」
  など、会話として自然な言葉を使う。

二人は、余裕のある年上の先生と、その先生に憧れながら学ぶ初心者という関係。掛け合いは
現代の学習室や保健室でも成立する、親しみのある師弟コメディにする。透の憧れは無邪気な
感情として扱い、澪は安心できる距離と選択肢を必ず残す。公開動画は健全な内容にする。

# 台本の設計指針

1. 想定視聴者は AI・ソフトウェア技術に関心のあるエンジニア。視聴者個人の属性
   （職業・経歴・年齢など）には言及しない。
2. 1 シーン 1 論点。冒頭シーンは「なぜ今この話題か」の導入、最終シーンは
   「結局何が重要か」のまとめ。
3. 出典に書かれていないことを断定しない。推測を述べる場合はセリフ内で推測だと分かるように。
4. セリフは `text`（字幕表示用）と `reading`（音声合成用の読み）の 2 本立てにする。
   - `text`: 英語の固有名詞・技術用語は自然な英語表記のまま（例: GitHub, pip, uv）。
   - `reading`: 同じ内容を音声合成が正しく読める形にする。英語はカタカナ化し
     （GitHub → ギットハブ、uv → ユーブイ）、数式・記号も読み下す。
   - text と reading は表記以外は同じ文章にする（内容を変えない）。
   - 名前の「透」は、`text` では「透くん」、`reading` では必ず「とおるくん」と書く。
   スライド側のテキストは英語表記のままでよい。
5. セリフ 1 つは 80 字以内。1 シーンのセリフは 2〜6 個。
6. 掛け合いは説明文を交互に読むだけにしない。透の疑問→澪の受け止め→説明、または
   澪の問いかけ→透の推測→補足、という因果を作る。少なくとも一度は、透の素朴な疑問で
   澪が説明の一段飛ばしに気づき、自然な言葉で説明を組み直す。
7. キャラクターらしい短いやり取りを2〜3シーンに一度だけ入れる。澪のからかいは一言で
   止め、透を追い詰めない。透は澪の落ち着いた説明に安心し、ときどき頬を赤らめる。
   澪は大人の余裕と華やかさを保ちつつ、透へは温かい先生として接する。毎回同じ口癖、
   過剰な色気、説明と無関係な恋愛会話は避ける。
8. 互いの名前を動画全体で自然に数回呼ぶ。透は「澪先生」、澪は「透くん」と呼ぶ。
   呼びかけを毎文に付けたり、機械的に交互配置したりしない。
9. 各セリフには `metan_pose` と `zunda_pose` を必ず付け、そのセリフ中に見せる表情を
   選ぶ。話の意味が変わる時だけ切り替え、毎行むやみに変えない。
   - `metan_pose`: `default`, `explain`, `point`, `praise`, `tease`, `wink`, `viewer`
   - `zunda_pose`: `default`, `listen`, `understand`, `confused`, `flustered`, `shy`, `praised`, `delighted`
   - `viewer` は澪が視聴者へ要点を説明する時、`tease` は軽いからかいに使う。
   - 澪が透を褒める場面は `metan_pose: praise` と `zunda_pose: praised` を組み合わせる。
     透は安心して正面を見るのではなく、頬を赤らめて澪から視線を逸らす。
   - 透の `flustered` と `shy` は無邪気な憧れや照れ、`delighted` は技術を理解した
     喜びに使う。澪は厳しい表情や、手のひらを正面へ向ける拒絶的なポーズを使わない。
10. スライドはセリフに同期して項目が順番に表示される。`bullets` / `outro` / `compare` の
   シーンでは各セリフに `show_items` (整数) を必ず付ける:
   - `bullets` / `outro`: そのセリフを話している間に見えている項目数 (1〜総数)。
     セリフがどの項目の話かに合わせ、シーン内で単調非減少、最後のセリフで必ず総数にする。
   - `compare`: 1 = 左カラムのみ表示、2 = 両カラム表示。最後は必ず 2。
   - `title` / `code` / `quote` のシーンには付けない。
11. 分量の目安: シーン数 8〜14、セリフ合計 3,000〜4,500 字（動画 5〜8 分相当）。
12. 各 `slide` に互換用の `background_mood` を付ける。通常の技術解説は `explain`、
    安全確認や注意点は `safety`、導入・まとめ・二人の温かな余韻は `warm` を使う。
    現行の動画では背景画像を切り替えず、同じ保健室背景を全シーンで固定する。
13. 台本トップレベルの `eyecatch_before_scenes` に、話題のまとまりが変わる直前の
    シーン番号を昇順で1〜2個指定する。全シーン間には入れず、概念説明→実践、
    実践→まとめなど、明確な章の境界だけを選ぶ。最初のシーンは指定しない。
    挿入順に別々の画像と楽器効果音が割り当てられる。最初は実践開始を明るく示す
    OtoLogic「木琴06-1（上昇・短）」、2回目は総復習への切り替えを柔らかく示す
    「グロッケン02-4（高・短）」を使う。人声の効果音は使わない。

# スライドテンプレート

各シーンの `slide.template` は以下のいずれか。全テンプレート共通で
`background_mood` (`explain | safety | warm`) を持たせ、下記フィールドも厳守すること。

- `title`: 表紙。fields: `heading`(動画タイトル), `subheading`(一言サブタイトル),
  `source_label`(出典表記、例 "Source: anthropic.com")
- `bullets`: 箇条書き。fields: `heading`, `items`(文字列 2〜5 個、各 40 字以内)
- `compare`: 2 カラム対比。fields: `heading`, `left_title`, `left_items`(2〜4 個),
  `right_title`, `right_items`(2〜4 個)
- `code`: コード・コマンド例。fields: `heading`, `code`(10 行以内), `caption`(1 行説明)
- `quote`: 原文引用。fields: `heading`, `quote`(引用文の日本語訳、60 字以内),
  `attribution`(出典表記)
- `outro`: まとめ。fields: `heading`, `items`(2〜4 個、各 40 字以内)

最初のシーンは必ず `title`、最後のシーンは必ず `outro`。中間は内容に合わせて選ぶ
（`bullets` ばかりにせず、対比には `compare`、具体例には `code` や `quote` を使う）。
