# 動画の形式

2 人のキャラクターの掛け合い（音声＋字幕）と、テンプレート化されたスライドで構成される
講義動画。スライドはセリフの「板書」であり、セリフの復唱ではない。

- `metan`（紫ノ宮澪）: 解説役。完璧な実務能力と大人の包容力を持つ先生。丁寧で
  落ち着いた大人の女性の口調で、相手を急かさず、失敗を恥にしない。通常の説明では
  主語と述語を備えた自然な文を使い、体言止めや説明書のような断片文を避ける。透の
  不安や淡い憧れには気づいているが利用しない。**通常は必ず敬語で話し、軽くからかう
  一言だけ敬語をやめる。** からかい以外で「〜だよ」「〜だね」などの非敬語を使わない。
- `zunda`（麦野透）: 聞き役。純朴で控えめな少年。**独り言、驚き、ツッコミを含む全ての
  セリフで、常に「です・ます」調の敬語を使う。** 分からないことを正直に尋ねる。自信は
  弱いが観察は細かく、ときどき澪の説明の飛躍や、数値と実物の矛盾を見つける。
  「〜のだ」など既存キャラクター固有の語尾は使わない。「もう迷いません」のような
  宣言調の不自然な要約を避け、状況に応じて「もう大丈夫です」「これならできそうです」
  など、会話として自然な言葉を使う。

二人は、余裕のある年上の先生と、その先生に憧れながら学ぶ初心者という関係。掛け合いは
現代の学習室や保健室でも成立する、親しみのある師弟コメディにする。透の憧れは無邪気な
感情として扱い、澪は安心できる距離と選択肢を必ず残す。公開動画は健全な内容にする。

口調の例:
- 透 ○「澪先生、この数字だけで判断してよいのでしょうか？」
  ×「この数字だけ見ればいいの？」
- 通常の澪 ○「まず、比較条件をそろえて確認しましょう。」
- からかう澪 (`metan_pose: tease`) ○「透くん、そんなに慌てなくてもいいのに。」

# 台本の設計指針

1. 想定視聴者は AI・ソフトウェア技術に関心のあるエンジニアのまま変えない。前提知識は
   高校生レベルまでとし、専門用語は初出前または初出と同じセリフで、日常語の定義と
   具体例・比喩を使って導入する。視聴者個人の属性（職業・経歴・年齢など）には言及しない。
2. 1 シーン 1 論点。冒頭シーンは、**困った透が澪へ相談する短い物語**にする。
   - 最初のセリフは必ず透が「澪先生」と呼びかけ、具体的な失敗、混乱、または違和感を
     敬語で話す。`zunda_pose` は `confused` または `flustered` にする。
   - 透を何も知らない役にせず、すでに何を試したか、どこが腑に落ちないかを示す。
   - 澪は困りごとを受け止め、問題の正体を一言で示してから、この動画で答える問いと
     全体像へ案内する。定義や動画タイトルの読み上げから始めない。
   - 特定の既存チャンネルの台詞、口癖、人物像、世界観は模倣しない。参考にするのは
     「具体的な困りごとから問いを立てる」という構成だけにする。
   最終シーンは、冒頭の困りごとへ戻って「結局何が重要か」と判断条件を回収する。
3. 出典に書かれていないことを断定しない。推測を述べる場合はセリフ内で推測だと分かるように。
   元URLやメールアドレスは、動画、スライド、概要欄のいずれにも出力しない。
4. セリフは `text`（字幕表示用）と `reading`（音声合成用の読み）の 2 本立てにする。
   - `text`: 英語の固有名詞・技術用語は自然な英語表記のまま（例: GitHub, pip, uv）。
   - `reading`: 同じ内容を音声合成が正しく読める形にする。英語はカタカナ化し
     （GitHub → ギットハブ、uv → ユーブイ）、数式・記号も読み下す。
   - text と reading は表記以外は同じ文章にする（内容を変えない）。
   - 名前の「透」は、`text` では「透くん」、`reading` では必ず「とおるくん」と書く。
   スライド側のテキストは英語表記のままでよい。
5. セリフ 1 つは 80 字以内。1 シーンのセリフは 2〜6 個。
6. 第2段階の教える順番に従う。基本線は、`透の困りごと → 中心の問い → 一文の答え →
   全体図 → 代表例 → 原理 → 一次資料・実測 → 失敗例・限界 → 判断 → 冒頭の回収`。
   掛け合いは説明文を交互に読むだけにしない。透の疑問→澪の受け止め→説明、または
   澪の問いかけ→透の推測→補足、という因果を作る。少なくとも一度は、透の素朴な疑問で
   澪が説明の一段飛ばしに気づき、自然な言葉で説明を組み直す。
   透には予想、誤解、反例、用語質問、新しい例への適用の仕事を分散し、「つまり」
   「〜のですね」「なるほど」だけの確認を全発話の25%以下にする。
7. キャラクターらしい短いやり取りを2〜3シーンに一度だけ入れる。澪のからかいは一言で
   止め、そのセリフだけ `metan_pose: tease` にして非敬語で話す。反対に、`tease` 以外の
   澪のセリフは必ず敬語にする。透を追い詰めない。透は澪の落ち着いた説明に安心し、
   ときどき頬を赤らめる。
   澪は大人の余裕と華やかさを保ちつつ、透へは温かい先生として接する。毎回同じ口癖、
   過剰な色気、説明と無関係な恋愛会話は避ける。
8. 互いの名前を動画全体で自然に数回呼ぶ。透は「澪先生」、澪は「透くん」と呼ぶ。
   呼びかけを毎文に付けたり、機械的に交互配置したりしない。
9. 各セリフには `metan_pose` と `zunda_pose` を必ず付け、そのセリフ中に見せる表情を
   選ぶ。話の意味が変わる時だけ切り替え、毎行むやみに変えない。
   - `metan_pose`: `default`, `explain`, `point`, `praise`, `tease`, `wink`, `viewer`
   - `zunda_pose`: `default`, `listen`, `understand`, `confused`, `flustered`, `shy`, `praised`, `delighted`
   - `viewer` は澪が視聴者へ要点を説明する時、`tease` は軽いからかいに使う。
   - 澪が透を褒める場面は `metan_pose: praise` と `zunda_pose: praised` を組み合わせる。
     透は安心して正面を見るのではなく、頬を赤らめて澪から視線を逸らす。
   - 透の `flustered` と `shy` は無邪気な憧れや照れ、`delighted` は技術を理解した
     喜びに使う。澪は厳しい表情や、手のひらを正面へ向ける拒絶的なポーズを使わない。
10. スライドはセリフに同期して項目が順番に表示される。`bullets` / `outro` / `compare` /
   `diagram` の
   シーンでは各セリフに `show_items` (整数) を必ず付ける:
   - `bullets` / `outro`: そのセリフを話している間に見えている項目数 (1〜総数)。
     セリフがどの項目の話かに合わせ、シーン内で単調非減少、最後のセリフで必ず総数にする。
   - `compare`: 1 = 左カラムのみ表示、2 = 両カラム表示。最後は必ず 2。
   - `diagram`: そのセリフの間に見えているノード数。シーン内で単調非減少、最後は全ノード。
   - `title` / `code` / `quote` / `figure` のシーンでは `show_items: null` にする。
11. シーン数8〜14、セリフ合計3,000〜4,500字を必ず守り、3,600〜4,200字を狙う。
    固定コードが上下限を検証する。透のセリフ数は全体の35〜50%にする。
    感嘆符・自然な間投詞・言い淀み・笑いを合計8個以上、かつ半数以上のシーンへ
    文脈に合わせて分散する。乱用や同じ間投詞の反復は避ける。
    透の発話中の`understand`は50%以下にし、各話者が自分の発話中に4種類以上の
    ポーズを使う。同一話者の7文字以上の口癖的なフレーズ反復は1件以下にする。
12. 各 `slide` に互換用の `background_mood` を付ける。通常の技術解説は `explain`、
    安全確認や注意点は `safety`、導入・まとめ・二人の温かな余韻は `warm` を使う。
    現行の動画では背景画像を切り替えず、同じ保健室背景を全シーンで固定する。
13. 台本トップレベルの `eyecatch_before_scenes` に、話題のまとまりが変わる直前の
    シーン番号を昇順で1〜2個指定する。全シーン間には入れず、概念説明→実践、
    実践→まとめなど、明確な章の境界だけを選ぶ。最初のシーンは指定しない。
    挿入順に別々の画像と楽器効果音が割り当てられる。最初は実践開始を明るく示す
    OtoLogic「木琴06-1（上昇・短）」、2回目は総復習への切り替えを柔らかく示す
    「グロッケン02-4（高・短）」を使う。人声の効果音は使わない。
14. 台本トップレベルの `thumbnail_text` は、YouTube サムネイルに大きく表示する
    2 行の短いコピーにする。各行は14文字以内。1行目は視聴者の疑問や意外性、2行目は
    動画で得られる具体的な便益を示す。動画内容から逸脱する煽り、性的な表現、年齢差を
    強調する表現は使わない。動画タイトルの単純な復唱ではなく、スマートフォンの縮小
    表示でも一瞬で意味が伝わる言葉を選ぶ。
15. 台本トップレベルの `thumbnail_visual_prompt` は、動画固有のサムネイル背景を
    ローカルSVGで描き分けるための短い美術案にする。240文字以内で、必ず先頭を
    `motif=<分類>;` とする。分類は `packages | network | code | security | database |
    cloud | research | speed | comparison | generic` のいずれか。続けて、動画の中心概念を
    象徴する具体的な物体・形・光・構図を日本語で記述する。人物、キャラクター、文字、
    ロゴは指定しない。澪・透と見出しは後段で固定素材として合成するため、中央には
    見出し用の静かな余白を残し、題材固有のモチーフは周辺へ置く。
16. **図解を優先する。** 関係・構造・手順・時間変化を視覚化できる論点を `bullets` に
    しない。次の順で選ぶ:
    1. 一覧に、論点を直接支える一次資料の図がある → `figure`
    2. 関係性を構造化できる → `diagram`
    3. 関係性を視覚化できない残余だけ → `bullets` / `quote`
17. `diagram_type` は説明対象の意味に合わせ、全シーンを同じ図型にしない。
    - `matrix`: 対立、トレードオフ、2軸で整理する4象限
    - `tree`: 派生、分類、親子関係。`items[0]`を親・根、残りを子にする
    - `flow`: 因果、処理順、データフロー
    - `layers`: 積層した依存関係、スタック、階層
    - `timeline`: 時間順の変化、段階的な展開
    - `cycle`: フィードバック、反復、循環
    - `table`: 実験値、仕様、複数手法などの定量比較
    単純な2者比較だけは `compare` を使う。`diagram.items` は表示順に2〜6個にする。
    `matrix` は左上→右上→左下→右下の4個にし、軸名をitemsへ重ねず、`left_title`を横軸、
    `right_title`を縦軸の名前にする。`table` は先頭行を見出しにし、同じ2〜4列を ` | ` で
    区切る（例: `指標 | 手法A | 手法B`）。数値の行列を `matrix` に入れない。複数要素を
    まとめる主体をtreeで示す場合、その主体を必ず`items[0]`へ置き、枝側へ置かない。
18. `figure` は一次資料の図をそのまま表示する。`figure_index` は上の一覧番号、`caption` は
    一覧のキャプションを正確に保ち、`attribution` は「資料名 — Figure N」の形にする。
    図の意味を変える要約や、本文で確認できない結論をキャプションへ加えない。

# スライドテンプレート

各シーンの `slide.template` は以下のいずれか。全テンプレート共通で
`background_mood` (`explain | safety | warm`) を持たせる。構造化出力の都合で、
下記にないスライドフィールドはすべて `null` にすること。

- `title`: 表紙。fields: `heading`(動画タイトル), `subheading`(一言サブタイトル),
  `source_label`(媒体名または資料名。URLやメールアドレスは禁止)
- `bullets`: 箇条書き。fields: `heading`, `items`(文字列 2〜5 個、各 40 字以内)
- `compare`: 2 カラム対比。fields: `heading`, `left_title`, `left_items`(2〜4 個),
  `right_title`, `right_items`(2〜4 個)
- `code`: コード・コマンド例。fields: `heading`, `code`(10 行以内), `caption`(1 行説明)
- `quote`: 原文引用。fields: `heading`, `quote`(引用文の日本語訳、60 字以内),
  `attribution`(出典表記)
- `diagram`: 関係性の図解。fields: `heading`, `diagram_type`
  (`flow | tree | layers | timeline | cycle | matrix | table`), `items`(2〜6個、matrixは4個)。
  matrixだけ `left_title`(横軸名), `right_title`(縦軸名) も使う。tableのitemsは同じ2〜4列を
  ` | ` で区切った行にする
- `figure`: 一次資料の図。fields: `heading`, `figure_index`, `caption`, `attribution`
- `outro`: まとめ。fields: `heading`, `items`(2〜4 個、各 40 字以内)

最初のシーンは必ず `title`、最後のシーンは必ず `outro`。中間は内容に合わせて選ぶ
（一次資料の図、意味に合う図解、テキストの順で検討する）。
